# 【訪問キャプチャシート】望月オート（来週訪問用）

> **使い方＝台本ではない。** 現場で「見る・写真に撮る・自然な会話で拾う」ためのメモ。順番も自由、埋まらない欄があってもOK。
> 目的は1つ：**帰ってきたら「共有ボード＋LINE更新」の最小構成をそのまま設計・構築できる**だけの生の事実を持ち帰ること。
> 拾った生の声は"言い換えず・そのまま" `CASE-mochizuki-whiteboard.md` に転記する（言い換えると価値が消える）。
> オーナー呼称＝タツヤ。返答は日本語。

---

## 0. まず最優先（これだけは絶対に持ち帰る）
- [ ] **ホワイトボードの全体写真**（引きで1枚＋寄りで数枚）。モニター表示中の様子も。
- [ ] **列（工程）の実際の並びと"現場の呼び名"**をそのまま書き写す（例：入庫→分解→板金→塗装→…）。
      → 提案では「入庫→分解→板金→塗装→組付→検査→納車待ち→納車済」と仮置き。**実際と違ったらここを正**にする。
- [ ] **行（1台）を何で識別しているか**：ナンバー／車名／お客さん名／担当者名？　→ スマホ表の「車の呼び方」がここで決まる。
- [ ] **付箋・マグネット・色分け・記号の意味**（赤＝急ぎ、等ルールがあれば全部）。

## 1. ホワイトボードの中身（＝スプレッドシートの列設計になる）
- 工程（列）は全部でいくつ？　抜けや「実は使ってない工程」はある？
- 1台の行に**工程以外に何が書いてある**？（担当者／納車予定日／代車／保険／部品待ち／お客さん連絡先 など）
- 「これはボードに必ず書く」という必須項目と、「あれば書く」項目の区別。
- 手書き特有の運用（矢印で飛ばす、二重線で消す、隅にメモ）で**デジタルに移すと困りそうな癖**はある？

## 2. 業務の流れ（＝更新頻度・タイミングの設計になる）
- 1日/1週あたり**入庫台数**、**同時進行している台数**の目安。
- 工程が「進んだ」瞬間は誰が・いつボードを動かす？（本人／事務／親方が朝まとめて 等）
- ボードを**1日に何回くらい**書き換える？（更新の頻度感＝LINE入力の頻度感）
- 外出するのは主に誰？　その人が「今どうなってる？」と一番知りたい場面は？（←🅐の刺さりどころ）

## 3. スマホ・LINE前提（＝実装が成立するかの確認）
- [ ] **全員スマホを持っている**か。ガラケーの人はいる？
- [ ] 普段**LINEを使っている**か（個人LINE／会社のグループLINEが既にある？）。
- 現場で入力するとき、**手が汚れている/手袋**でも打てるか？　→ 音声入力が要るかの判断。
- 「文字を打つ」より「喋る」方が自然か？（🅑の入力方式＝テキスト/音声どちらを主にするか）
- 事務所のPC/ネット環境、Wi-Fi、Googleアカウントの有無（＝スプレッドシートの土台）。

## 4. 通知ニーズ（＝🅒先回り通知の"刺さる例"を集める）
> 「あったら嬉しい通知」を**具体例で**拾う。抽象論より「先週まさに困った実例」が金。
- 「これは早く気づきたかった」という**直近の実例**（納期被り／塗装で止まってた／部品待ちで放置 等）。
- 社長が欲しい通知と、職人さんが欲しい通知は**違う**かもしれない → 両方から拾う。
- 逆に「通知が多いと鬱陶しい」ラインも聞く（通知しすぎない設計のため）。

## 5. 人・空気（この会社ならではの設計判断）
- 女性の職人さんが多い・雰囲気が良い会社。**「新しいアプリは覚えたくない」度合い**を体感で掴む。
- 「これだけは今のやり方を変えたくない」というこだわりポイント。
- 逆に社長が「AIで全部やりたい」と言っている**"全部"の中身**（見積もり／集客／LINE対応／原価 等、どれから期待？）。
      → ここは別案件（塗料原価システム）や他メニューへの横展開の種になる。別ファイルに切り出す。

## 6. 無料テストの握り（現場で口頭合意まで持っていけると理想）
- テスト対象＝**全社いっぺん**か、**1ライン/数台に絞る**か（絞る方が立ち上げやすい）。
- テスト期間の目安（提案は1〜2ヶ月）。「テストは無料／本格運用・横展開は有償」を**最初に伝える**。
- [ ] **「事例として使わせてもらう」許可**の感触（実績0→1の本体）。
- 誰が「現場の主担当（一緒に触ってくれる人）」になれそうか。

## 帰社後の段取り（このシートが埋まったら）
1. 生の声・写真を `CASE-mochizuki-whiteboard.md` の「現況」に転記。
2. 上の 1・2 をもとに **スプレッドシートの列（工程）を確定** → 共有ボードの最小構成を設計。
3. 3・4 をもとに **LINE→Claude→Sheets の更新フロー**と**通知ルール**を具体化。
4. 6 の握りをもとにテスト範囲・期間を1枚で固める。
   → ここまで来たら実装（構築）に着手できる。
